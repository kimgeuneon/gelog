## 지금 블로그 구성

| 항목 | 내용 |
|---|---|
| 프레임워크 | Astro 7 (정적 사이트 생성) |
| 통합 | MDX, sitemap, RSS, React |
| 스타일 | 전역 CSS 한 벌(`global.css`), 빌드 후 CSS 약 8KB |
| 배포 | GitHub Actions → GitHub Pages, 커스텀 도메인 `gelog.co.kr` |
| 캐시 | GitHub Pages CDN(Varnish), `max-age=600` |
| 댓글 | FastAPI 백엔드(배포 예정), 프런트는 작은 스크립트 |

## 로딩 속도 측정 결과

| 페이지 | 전송 크기 | 첫 바이트까지 |
|---|---|---|
| 홈 `/` | 약 1.7KB(압축) | 약 0.3초 |
| 글 목록 `/blog/` | 약 2KB(압축) | 약 0.26초 |
| 비밀 게시판 `/private/` | 약 5MB | 약 1.1초 |

일반 페이지는 이미 매우 가볍습니다. 정적 HTML에 자바스크립트가 거의 없기 때문입니다. 무거운 곳은 비밀 게시판 하나입니다.

## 속도를 더 줄이는 방법

### 1. React는 필요한 곳에만

- 댓글과 비밀 게시판은 React 컴포넌트입니다. Astro의 아일랜드 방식이라 그 컴포넌트가 있는 페이지에만 React 런타임이 실리고, 글 본문 같은 정적인 부분은 HTML 그대로 나갑니다.
- 댓글은 `client:visible`로 화면에 보일 때 붙고, 비밀 게시판은 `client:load`로 바로 붙습니다.

### 2. 비밀 게시판의 영상 분리

- 처음에는 암호화된 데이터가 영상까지 통째로 페이지 HTML 안에 있어서 약 6.5MB였습니다. base64는 원본보다 약 33% 커지고, 페이지를 열 때 한 번에 내려받아야 했습니다.
- 지금은 이렇게 나눴습니다.
  - 글 목록과 본문은 작은 암호화 파일 하나로 따로 두고, 페이지 HTML에는 잠금 화면만 있습니다.
  - 영상이 든 발표 슬라이드는 글마다 따로 암호화해서, 그 글을 열 때만 받습니다.
  - 파일은 모두 같은 키로 잠가서 비밀번호는 한 번만 넣습니다.

### 3. 웹폰트 최적화

- 한글 웹폰트는 크기가 커서 첫 화면 표시를 늦추는 주범입니다.
- 쓰는 글자만 남기는 서브셋, `woff2`, `font-display: swap`, 첫 화면 폰트만 `preload`하는 방식으로 줄입니다.

### 4. 이미지

- 글 안 이미지는 Astro의 `<Image />`로 넣으면 AVIF/WebP 변환, 크기 지정, 지연 로딩이 자동으로 됩니다.

### 5. 캐시

- GitHub Pages는 캐시 헤더를 바꿀 수 없어서 `max-age=600`(10분)으로 고정입니다. Astro가 만드는 `_astro/` 파일은 이름에 해시가 붙어 있으니, 더 길게 캐시하고 싶으면 Cloudflare 같은 CDN을 앞에 두는 방법이 있습니다. 지금 트래픽 규모에서는 필수는 아닙니다.

## AI slop 디자인이란

AI 도구나 템플릿으로 만든 사이트에서 반복해서 보이는 특징이 있습니다.

- 보라·파랑 그라디언트 배경과 그라디언트 글자
- 둥근 모서리 카드 + 옅은 그림자 + 이모지 아이콘을 3개씩 나열
- "Unlock", "Seamless", "Elevate" 같은 뜻 없는 문구
- 모든 섹션이 가운데 정렬, 같은 여백, 같은 크기
- 반짝이는 블러·글래스모피즘 효과
- Inter 폰트 하나로 모든 것을 처리

문제는 각각이 나빠서가 아니라 **누가 만든 사이트인지 알 수 없다는 것**입니다.

## 벗어나는 방법

### 1. 글꼴부터 바꾸기

- 글꼴이 가장 빠른 탈출구입니다. Inter, Roboto, 시스템 기본 글꼴은 아무 선택도 하지 않았다는 신호로 읽힙니다.
- 본문은 읽기 좋은 글꼴 하나, 제목은 성격이 다른 글꼴 하나로 **두 개까지만** 씁니다. 제목에 세리프나 모노스페이스를 쓰면 같은 레이아웃이라도 인상이 크게 달라집니다.
- 한글은 선택지가 적어서 Pretendard가 기본값처럼 쓰입니다. 본문은 그대로 두더라도 제목·숫자·코드에 다른 글꼴을 쓰면 기본값 느낌이 사라집니다.

### 2. 정해진 색 세 가지만 쓰기

- 배경, 글자, 강조색 세 가지로 제한합니다. 비율은 대략 60 : 30 : 10입니다.
- 강조색은 링크, 핵심 숫자, 버튼처럼 **눌러야 하거나 봐야 하는 곳**에만 씁니다. 장식으로 쓰면 바로 템플릿처럼 보입니다.
- 보라·파랑 그라디언트는 가장 널리 알려진 AI 표식입니다. 제목 글자에 그라디언트를 입히는 것도 같습니다.
- 색을 CSS 변수로 한 곳에 정의하고, 그 밖의 색은 쓰지 않습니다.

### 3. 간격과 정렬로 느낌을 만들기

- 인터페이스의 인상은 색보다 간격, 리듬, 정렬선이 정합니다.
- 여백 단계를 4~5개(예: 4 · 8 · 16 · 32 · 64px)로 정하고 그 값만 씁니다. 모든 요소에 같은 패딩과 같은 모서리 반지름을 주는 것이 전형적인 기본값 느낌입니다.
- 왼쪽 정렬을 기본으로 합니다. 모든 섹션을 가운데 정렬하는 것은 템플릿의 습관입니다.
- 본문 한 줄은 한글 기준 35~45자로 맞춥니다.

### 4. 카드 습관 버리기

- 둥근 모서리 + 옅은 그림자 + 이모지 아이콘 3개 나열, 색 띠가 붙은 카드, 카드 안의 카드, 반투명 유리 효과(글래스모피즘)는 가장 흔한 표식입니다.
- 카드 대신 **배경색 차이와 간격**으로 영역을 나눕니다. 글 목록은 카드보다 "날짜 · 제목 · 한 줄 요약" 목록이 더 읽기 좋은 경우가 많습니다.
- 테두리와 그림자는 정말 구분이 필요한 곳 한두 군데에만 남깁니다.

### 5. 진짜 내용으로 채우기

- "Unlock", "Seamless", "Elevate" 같은 문구와 스톡 이미지는 내용이 없다는 신호입니다.
- 첫 화면에는 무엇을 하는 사람인지 구체적인 문장 하나를 씁니다. 예: "로봇이 집안일을 하게 만드는 평가 시스템을 만듭니다."
- 장식 대신 실제 결과물을 보여 줍니다. 로봇 영상, 대시보드 캡처, 직접 그린 다이어그램이 어떤 그라디언트보다 사이트를 구별되게 합니다.

### 6. 움직임은 적게, 목적이 있을 때만

- 애니메이션은 `transform`과 `opacity`만, 300ms 이내로 제한하고 `prefers-reduced-motion`을 따릅니다.
- 스크롤할 때마다 요소가 떠오르는 효과, 배경에서 떠다니는 도형은 템플릿의 표식입니다. 상태가 바뀌는 순간(열림, 선택, 완료)에만 움직임을 둡니다.

### 7. 참고할 실제 사이트를 정하기

- "모던하게", "깔끔하게" 같은 형용사 대신 **구체적인 사이트 한두 개**를 기준으로 정합니다. 제목 크기, 간격, 색 사용을 그 기준과 비교하면 판단이 쉬워집니다.
- 기억에 남는 요소는 **하나만** 정합니다. 게임 HUD, 터미널, 손 그림 다이어그램처럼요. 그것을 헤더, 글 목록, 404 페이지 정도에만 일관되게 씁니다. 전부 꾸미면 다시 템플릿이 됩니다.

### 8. AI 도구를 쓸 때는 제약을 먼저 주기

- 생성 도구는 기본값으로 수렴합니다. 색, 글꼴, 간격, 모서리 값을 파일 하나에 적어 두고 그것만 따르게 하면 화면마다 기본값으로 되돌아가는 일이 줄어듭니다.
- 피할 것을 명시합니다. 보라 그라디언트, 가운데 정렬 배지 + 제목 + 카드 3개, Inter, 유리 효과처럼 이름을 붙여 금지하는 것이 "예쁘게"보다 효과가 큽니다.
- 만든 뒤에는 위 1~7 기준으로 한 번 점검하고, 가장 눈에 띄는 문제 하나를 고치고 다시 보는 식으로 반복합니다.

## 정리

AI slop 디자인의 공통점은 **선택하지 않은 기본값**입니다. 글꼴, 색 세 가지, 간격 단계, 기준 사이트 하나. 이 네 가지만 직접 정해도 누가 만든 사이트인지 보이기 시작합니다.
