## 지금 블로그 구성

| 항목 | 내용 |
|---|---|
| 프레임워크 | Astro 7 (정적 사이트 생성) |
| 통합 | MDX, sitemap, RSS, React |
| 스타일 | 전역 CSS 한 벌(`global.css`), 빌드 후 CSS 약 8KB |
| 배포 | GitHub Actions → GitHub Pages, 커스텀 도메인 `gelog.co.kr` |
| 캐시 | GitHub Pages CDN(Varnish), `max-age=600` |
| 댓글 | FastAPI 백엔드(배포 예정), 프런트는 작은 스크립트 |

## 로딩 속도 측정 결과

| 페이지 | 전송 크기 | 첫 바이트까지 |
|---|---|---|
| 홈 `/` | 약 1.7KB(압축) | 약 0.3초 |
| 글 목록 `/blog/` | 약 2KB(압축) | 약 0.26초 |
| 비밀 게시판 `/private/` | 약 5MB | 약 1.1초 |

일반 페이지는 이미 매우 가볍습니다. 정적 HTML에 자바스크립트가 거의 없기 때문입니다. 무거운 곳은 비밀 게시판 하나입니다.

## 속도를 더 줄이는 방법

### 1. React는 필요한 곳에만

- 댓글과 비밀 게시판은 React 컴포넌트입니다. Astro의 아일랜드 방식이라 그 컴포넌트가 있는 페이지에만 React 런타임이 실리고, 글 본문 같은 정적인 부분은 HTML 그대로 나갑니다.
- 댓글은 `client:visible`로 화면에 보일 때 붙고, 비밀 게시판은 `client:load`로 바로 붙습니다.

### 2. 비밀 게시판의 영상 분리

- 처음에는 암호화된 데이터가 영상까지 통째로 페이지 HTML 안에 있어서 약 6.5MB였습니다. base64는 원본보다 약 33% 커지고, 페이지를 열 때 한 번에 내려받아야 했습니다.
- 지금은 이렇게 나눴습니다.
  - 글 목록과 본문은 작은 암호화 파일 하나로 따로 두고, 페이지 HTML에는 잠금 화면만 있습니다.
  - 영상이 든 발표 슬라이드는 글마다 따로 암호화해서, 그 글을 열 때만 받습니다.
  - 파일은 모두 같은 키로 잠가서 비밀번호는 한 번만 넣습니다.

### 3. 웹폰트 최적화

- 한글 웹폰트는 크기가 커서 첫 화면 표시를 늦추는 주범입니다.
- 쓰는 글자만 남기는 서브셋, `woff2`, `font-display: swap`, 첫 화면 폰트만 `preload`하는 방식으로 줄입니다.

### 4. 이미지

- 글 안 이미지는 Astro의 `<Image />`로 넣으면 AVIF/WebP 변환, 크기 지정, 지연 로딩이 자동으로 됩니다.

### 5. 캐시

- GitHub Pages는 캐시 헤더를 바꿀 수 없어서 `max-age=600`(10분)으로 고정입니다. Astro가 만드는 `_astro/` 파일은 이름에 해시가 붙어 있으니, 더 길게 캐시하고 싶으면 Cloudflare 같은 CDN을 앞에 두는 방법이 있습니다. 지금 트래픽 규모에서는 필수는 아닙니다.

## AI slop 디자인이란

AI 도구나 템플릿으로 만든 사이트에서 반복해서 보이는 특징이 있습니다.

- 보라·파랑 그라디언트 배경과 그라디언트 글자
- 둥근 모서리 카드 + 옅은 그림자 + 이모지 아이콘을 3개씩 나열
- "Unlock", "Seamless", "Elevate" 같은 뜻 없는 문구
- 모든 섹션이 가운데 정렬, 같은 여백, 같은 크기
- 반짝이는 블러·글래스모피즘 효과
- Inter 폰트 하나로 모든 것을 처리

문제는 각각이 나빠서가 아니라 **누가 만든 사이트인지 알 수 없다는 것**입니다.

## 벗어나는 방법

이 블로그를 다시 열어 보면 제목에 그라디언트가 들어가 있고, 글 목록은 둥근 카드로 되어 있습니다. 위에서 적은 표식 중 두 개가 첫 화면에 있는 셈입니다. 어디서부터 손을 대야 하는지 순서대로 적어 봅니다.

### 글꼴

가장 먼저 티가 나는 것은 글꼴입니다. Inter나 시스템 기본 글꼴을 그대로 두면, 사이트를 만든 사람이 글꼴에 대해 아무 결정도 하지 않았다는 뜻이 됩니다. 꼭 화려한 글꼴일 필요는 없고, 결정을 했다는 흔적이 있으면 됩니다.

한글 사이트는 선택지가 좁아서 대부분 Pretendard로 수렴합니다. 이 블로그도 그렇습니다. 본문은 Pretendard를 그대로 두더라도, 제목이나 날짜, 코드처럼 눈이 머무는 곳에 다른 계열의 글꼴을 하나 섞으면 분위기가 달라집니다. 제목에 세리프를 쓰거나 숫자에 모노스페이스를 쓰는 식입니다. 다만 두 개까지입니다. 세 개부터는 다시 산만해집니다.

### 색

색은 배경, 글자, 강조색 세 가지면 충분합니다. 강조색은 링크나 버튼, 꼭 봐야 하는 숫자처럼 눌러야 하거나 봐야 하는 곳에만 씁니다. 제목을 꾸미려고 쓰는 순간 템플릿처럼 보이기 시작합니다. 보라색에서 파란색으로 흐르는 그라디언트가 대표적이고, 제목 글자에 그라디언트를 입히는 것도 마찬가지입니다. 이 블로그의 `gradient-text`가 바로 그것입니다.

색을 CSS 변수로 한 곳에 모아 두면 나중에 새 색이 끼어드는 것을 막기 쉽습니다. 변수에 없는 색은 쓰지 않는다는 규칙 하나로 충분합니다.

### 간격과 정렬

색보다 간격이 인상을 더 많이 정합니다. 여백 단계를 네다섯 개로 정해 두고(4, 8, 16, 32, 64px처럼) 그 값만 쓰면, 디자인을 따로 배우지 않아도 화면에 리듬이 생깁니다. 반대로 모든 요소에 같은 패딩과 같은 모서리 반지름을 주는 것이 기본값 느낌의 정체입니다.

정렬은 왼쪽이 기본입니다. 섹션마다 가운데 정렬을 하면 글이 아니라 랜딩 페이지처럼 읽힙니다. 본문 한 줄은 한글 기준 35~45자 정도가 읽기 편합니다.

### 카드

둥근 모서리에 옅은 그림자, 그 안에 이모지 아이콘과 짧은 제목이 세 개 나란히 있는 구성은 거의 모든 AI 생성 페이지에 들어 있습니다. 색 띠가 붙은 카드, 카드 안에 또 카드, 반투명 유리 효과도 같은 부류입니다.

카드를 없애고 배경색 차이와 간격만으로 영역을 나눠도 구분은 충분히 됩니다. 글 목록은 카드보다 "날짜, 제목, 한 줄 요약"이 나란히 있는 목록이 훑어보기 좋습니다. 테두리와 그림자는 정말로 구분이 필요한 한두 군데에만 남깁니다.

### 내용

"Seamless", "Elevate" 같은 단어와 스톡 이미지는 그 자리에 넣을 내용이 없었다는 고백에 가깝습니다. 첫 화면에는 무엇을 하는 사람인지 한 문장으로 씁니다. "로봇이 집안일을 하게 만드는 평가 시스템을 만듭니다" 정도면 됩니다.

장식 대신 실제 결과물을 보여 주는 것이 사이트를 가장 확실하게 구별되게 만듭니다. 로봇이 움직이는 영상, 대시보드 캡처, 직접 그린 다이어그램 같은 것들입니다. 이것은 다른 누구도 가져갈 수 없습니다.

### 움직임

애니메이션은 `transform`과 `opacity`만 쓰고 300ms 안에 끝내며, `prefers-reduced-motion`을 따릅니다. 스크롤할 때마다 요소가 떠오르는 효과나 배경에서 떠다니는 도형은 템플릿의 흔적입니다. 무언가 열리거나 선택되거나 끝났을 때처럼 상태가 바뀌는 순간에만 움직임을 두면 됩니다.

### 기준 사이트

"모던하게", "깔끔하게" 같은 말은 판단 기준이 되지 못합니다. 대신 좋아하는 사이트 한두 개를 정해 두고, 제목 크기나 간격, 색 사용을 그 사이트와 나란히 놓고 비교합니다. 그러면 고칠 곳이 바로 보입니다.

기억에 남는 요소는 하나만 고릅니다. 게임 HUD든 터미널이든 손 그림 다이어그램이든, 그것을 헤더와 글 목록, 404 페이지 정도에만 일관되게 쓰면 됩니다. 사이트 전체를 꾸미면 다시 템플릿이 됩니다.

### AI 도구를 쓸 때

생성 도구는 아무 말도 하지 않으면 기본값으로 돌아갑니다. 색과 글꼴, 간격, 모서리 값을 파일 하나에 적어 두고 그것만 따르게 하면 화면마다 결과가 흔들리는 일이 줄어듭니다. 피할 것도 이름을 붙여 적습니다. 보라 그라디언트, 가운데 정렬된 배지와 제목과 카드 세 개, Inter, 유리 효과. "예쁘게 해 줘"보다 이쪽이 훨씬 잘 듣습니다.

만든 뒤에는 위 항목을 기준으로 한 번 훑어보고, 가장 거슬리는 것 하나만 고치고 다시 봅니다. 한 번에 다 고치려고 하면 어디가 나아졌는지 알 수 없습니다.

## 정리

AI slop 디자인의 공통점은 선택하지 않은 기본값입니다. 글꼴 하나, 색 세 가지, 간격 단계, 기준 사이트 하나. 이 정도만 직접 정해도 누가 만든 사이트인지 보이기 시작합니다. 이 블로그도 제목 그라디언트와 카드 목록부터 바꿀 생각입니다.
