## 한눈에 보기

| | vLLM | SGLang | DeepInfer |
|---|---|---|---|
| 만든 곳 | UC Berkeley에서 시작, 커뮤니티 | LMSYS에서 시작, 커뮤니티 | DeepSeek |
| 성격 | 범용 서빙 엔진 | 범용 서빙 엔진 + 프로그래밍 프런트엔드 | DeepSeek 모델 전용 참고 엔진 |
| 핵심 기술 | PagedAttention | RadixAttention | DeepSeek 서빙 스택의 커널·스케줄링 |
| 강점 | 넓은 모델·하드웨어 지원, 큰 생태계 | 접두어 공유, 구조화 출력, 에이전트 워크로드 | DeepSeek 모델에 맞춘 최적화 |
| 약점 | 복잡한 다단계 호출은 직접 짜야 함 | 지원 범위가 vLLM보다 좁은 편 | 범용성 없음, 운영 구성요소 부족 |

## 공통 배경: 서빙이 어려운 이유

LLM 서빙의 병목은 대부분 **KV 캐시**입니다. 요청마다 앞에서 계산한 key/value를 GPU 메모리에 들고 있어야 하는데, 길이가 제각각이라 메모리가 조각나고 낭비됩니다. 세 엔진 모두 이 문제를 어떻게 푸느냐에서 갈립니다.

## vLLM

- **PagedAttention**: 운영체제의 가상 메모리처럼 KV 캐시를 작은 블록(페이지)으로 나눠 관리합니다. 메모리 낭비가 크게 줄어 한 GPU에 더 많은 요청을 올릴 수 있습니다.
- **Continuous batching**: 요청이 끝나는 대로 빈자리에 새 요청을 넣어 GPU를 쉬지 않게 합니다.
- **Automatic prefix caching**: 같은 앞부분(시스템 프롬프트 등)을 공유하는 요청은 KV 캐시를 재사용합니다.
- 양자화, speculative decoding, LoRA 서빙, 텐서·파이프라인 병렬화를 지원합니다.
- NVIDIA·AMD·TPU 등 하드웨어 지원과 모델 지원 범위가 가장 넓습니다. OpenAI 호환 서버로 바로 띄울 수 있어 "일단 서빙"에는 가장 무난한 선택입니다.

## SGLang

- **RadixAttention**: 요청들의 KV 캐시를 접두어 트리(radix tree)로 관리합니다. 여러 요청이 앞부분을 공유하는 경우(멀티턴 대화, few-shot, 에이전트의 반복 호출)에 캐시 재사용률이 높습니다.
- **구조화 출력**: JSON 스키마·정규식 제약 디코딩이 빠릅니다. 도구 호출처럼 형식이 정해진 출력에 유리합니다.
- **프런트엔드 언어**: 생성·분기·병렬 호출을 파이썬 코드로 묶어 쓰는 DSL이 있어, 여러 단계로 LLM을 부르는 프로그램을 짜기 쉽습니다.
- 스케줄러 오버헤드를 줄인 설계와 DeepSeek 계열 MoE 모델 최적화(데이터 병렬 어텐션, 전문가 병렬)로 대규모 배포에서 많이 쓰입니다.
- KV 캐시 시스템, prefill·decode 분리, 로드 밸런서 같은 운영 구성요소를 함께 갖추고 있습니다.

## DeepInfer

공개된 지 얼마 되지 않아 아래 내용은 공식 README와 2차 보도를 기준으로 정리했습니다. 수치는 버전에 따라 바뀔 수 있습니다.

- DeepSeek이 자사 서빙 스택에서 떼어 공개한 **오프라인 추론 엔진**입니다.
- 범용 엔진이 아니라 **DeepSeek 모델에 맞춘 참고 구현**에 가깝습니다. README에 vLLM을 출발점으로 삼고 SGLang·TensorRT-LLM에서 영감을 받았다고 밝혔습니다.
- 공개 뒤 SGLang과 vLLM이 같은 하드웨어·조건에서 DeepInfer 성능을 따라잡았거나 넘었다고 발표했습니다(SGLang은 prefill 처리량, vLLM은 decode 처리량 기준).
- 오픈소스 버전에는 KV 캐시 시스템, prefill·decode 분리, 로드 밸런싱 같은 운영 구성요소가 SGLang만큼 갖춰져 있지 않다는 평가가 있습니다.

## 고르는 기준

- **여러 모델을 무난하게 서빙**: vLLM
- **에이전트, 멀티턴, 같은 프롬프트를 반복 호출, JSON 출력이 많음**: SGLang
- **DeepSeek 모델 내부 최적화를 공부하거나 기준선으로 비교**: DeepInfer
- 실제 선택은 내 모델·GPU·요청 패턴으로 직접 벤치마크해서 정하는 것이 가장 정확합니다. 엔진 간 순위는 버전이 오를 때마다 바뀝니다.
