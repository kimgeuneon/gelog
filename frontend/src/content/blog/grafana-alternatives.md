## 먼저 짚을 점: Grafana는 저장소가 아님

"Grafana를 대체한다"고 할 때는 두 층을 나눠서 봐야 합니다.

| 층 | 하는 일 | 대표 도구 |
|---|---|---|
| 시각화 | 대시보드, 쿼리 화면, 알림 | Grafana, Kibana, SigNoz UI |
| 저장·검색 | 로그를 받아 저장하고 찾기 | Loki, Elasticsearch/OpenSearch, ClickHouse, VictoriaLogs |

Grafana 자체는 데이터를 저장하지 않습니다. 로그 쪽 불만은 대부분 Grafana가 아니라 그 뒤의 **Loki**에서 나옵니다. 그래서 대안도 "시각화만 바꾸기"와 "저장소째 바꾸기"로 나뉩니다.

## Grafana + Loki 조합의 단점

### Loki의 검색 방식

- Loki는 로그 본문을 색인하지 않고 **라벨만 색인**합니다. 저장 비용이 싼 대신, 본문 검색은 해당 기간의 청크를 전부 읽어서 거릅니다.
- 그래서 "최근 30일 전체에서 이 에러 문자열 찾기" 같은 전문 검색은 느립니다.
- 라벨을 많이 쪼개면(예: 에피소드 ID, 요청 ID를 라벨로) **카디널리티 폭발**로 스트림이 너무 많아져 성능이 급격히 나빠집니다. 라벨 설계를 처음부터 신경 써야 합니다.

### LogQL·PromQL 학습 비용

- 메트릭은 PromQL, 로그는 LogQL로 쿼리 언어가 둘입니다.
- 간단한 필터는 쉽지만 집계·파싱이 섞이면 쿼리가 금방 길어집니다.

### 대시보드 관리

- 대시보드가 긴 JSON이라 리뷰와 버전 관리가 어렵습니다. 화면에서 고친 내용이 코드와 어긋나기 쉽습니다.
- 대시보드가 쌓이면 누가 무엇을 보는지 정리가 안 됩니다.

### 운영 부담

- 셀프 호스팅이면 Grafana, Loki, Prometheus, 수집 에이전트를 각각 띄우고 보관 기간·디스크를 관리해야 합니다.
- 알림(Alerting)은 기능이 많은 대신 설정 구조가 복잡합니다.

### 라이선스

- Grafana와 Loki는 2021년부터 AGPLv3입니다. 사내에서 그대로 쓰는 데는 문제가 없지만, 수정해서 외부 서비스로 제공하면 소스 공개 의무를 검토해야 합니다.

## 대안 정리

| 도구 | 저장 방식 | 강점 | 약점 | 어울리는 상황 |
|---|---|---|---|---|
| **ELK / OpenSearch + Kibana** | 역색인(전문 색인) | 빠른 전문 검색, 오래된 생태계 | 색인 때문에 디스크·메모리 사용량 큼 | 로그 본문 검색이 핵심일 때 |
| **SigNoz** | ClickHouse | 로그·메트릭·트레이스를 한 UI에서, OpenTelemetry 기본 | 셀프 호스팅 시 ClickHouse 운영 | Grafana 스택 여러 개를 하나로 줄이고 싶을 때 |
| **ClickStack (HyperDX + ClickHouse)** | ClickHouse | SQL로 로그 분석, 높은 압축률 | 비교적 새 도구 | 로그를 데이터처럼 집계·분석할 때 |
| **VictoriaLogs** | 자체 컬럼 저장 | 가볍고 빠름, 단일 바이너리, 높은 카디널리티에 강함 | UI는 Grafana 플러그인에 기대는 편 | Loki를 그대로 바꿔 끼우고 싶을 때 |
| **Datadog / Better Stack / Axiom** | SaaS | 설치·운영이 거의 없음 | 로그 양에 비례해 비용 증가 | 운영 인력이 없을 때 |
| **Foxglove** | MCAP·rosbag 파일 | 로봇 토픽·카메라·3D를 시간축으로 재생 | 서버 로그 수집 도구는 아님 | 로봇 실행 기록을 되짚을 때 |

## 상황별 선택

- **지금 구조(Alloy → Prometheus·Loki → Grafana)를 유지**: 메트릭은 그대로 두고, 로그 검색이 답답하면 Loki만 **VictoriaLogs**로 바꾸는 것이 변경 범위가 가장 작습니다.
- **로그·메트릭·트레이스를 한 화면으로**: **SigNoz**처럼 OpenTelemetry 기반 통합 도구가 맞습니다.
- **에러 문자열을 자주 찾음**: 전문 색인이 있는 **OpenSearch**가 맞습니다.
- **로봇 실행 자체를 되돌려 보기**: 서버 로그 도구와 별개로 **Foxglove + MCAP**를 함께 씁니다.

## 정리

Grafana는 시각화 도구로서는 여전히 좋은 선택입니다. 바꿀 대상은 대개 로그 저장소이고, 무엇을 가장 자주 찾는지(문자열, 집계, 시간축 재생)에 따라 고르면 됩니다.
